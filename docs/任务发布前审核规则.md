# 任务发布前审核规则

规则版本：1.0；适用主线：1.2 及以后；适用所有新任务、续跑与实质变更。

## 一、两个审核不能混用

发布前是设计审核：判断范围、依据、实施方法和验收条件能否放行。完成后是执行验收：核对真实代码、配置、产物、命令与测试。前者不能代替后者。

## 二、每次固定流程

读取当前主线/状态/实际证据 -> 起草任务 -> 四方向提出问题 -> 修订任务 -> 记录遗留风险和前置条件 -> 绑定 task_version 与正文版本 -> 放行 -> 执行前核验 -> 任务后验收。

审批可绑定同一 Git commit 中的任务与审核文件；也可绑定任务正文 SHA256。不得只写“已审核”而不说明审的是哪一版。任何实质修改都需新的任务版本和复审。

## 三、四方向最低检查项

| 方向 | 必答问题 |
| --- | --- |
| 几何/可见光 | 来源、尺度、变体、构型和材质是否可信？生产副本与原始资料是否分离？缺失几何是否被猜造？ |
| 运动/可动结构 | 状态是否连续、同钟、可解释？旋翼相位与机体/观测运动是否一致？保真等级是否被夸大？ |
| 热学/红外 | 温度、辐射、光学、时序、采样、噪声和数字处理域是否明确？假设和实测是否混淆？是否有数值检验？ |
| 工程/数据 | 输入、写入范围、回归、资源预算、标签、划分、许可、发布边界和回滚是否明确？是否存在泄漏或循环证明？ |

不相关的检查项记录 NOT_APPLICABLE 及理由；不能删掉某个方向。

## 四、最小审核记录

review_id；task_id；task_version；mainline_version；审阅的 commit/正文哈希；review_mode；四方向问题；逐条处置；未决项；可执行范围；阻塞范围；复审触发条件；结论。

单助手四视角桌面审核写 SINGLE_ASSISTANT_FOUR_PERSPECTIVE_DESIGN_REVIEW。多个独立执行环境实际审查才可写独立审核，并附各自证据。不得虚构专家、代理会话或测试。

## 五、放行状态

- APPROVED：已检查范围可执行。
- APPROVED_WITH_GATES：仅在任务规定的前置检查通过后执行对应步骤。
- NEEDS_REVISION：先改任务，不运行受影响步骤。
- BLOCKED：缺关键输入/权限，明确需要什么。

上述状态都不是 G2/G4 或物理真实度通过。某个可独立子步骤被阻塞，不自动阻塞无关工作；但不能越过其下游依赖。

## 六、执行前与执行后

执行前保存主线 commit、本地 revision、任务版本、输入哈希与假设清单；不覆盖原始输入。先小测再扩展，资源越界停止，报告不能以降低门槛凑通过。

执行后列出实际命令/环境/输出、测试分母分子、失败项和未运行项。保留设计审核与执行验收两份记录，按授权更新状态。

## 七、命名与安全

新增阶段、任务、报告使用中文；编号保留在元数据。公共仓库只存可公开内容，原始技术方案、实拍、设备详参和受限模型留本地。每次发布核对文件白名单，不通过删除历史记录掩盖失误。
